# 1. 数据库到底是什么？

假设你要保存用户：

```text
id | name  | email
---+-------+----------------
1  | Alice | alice@test.com
2  | Bob   | bob@test.com
```

这就是一张 **table（表）**。

其中：

```text
User table
│
├── column: id
├── column: name
└── column: email
```

每一条：

```text
1 | Alice | alice@test.com
```

叫一行：

> row / record

所以最基础的关系数据库模型就是：

```text
Database
│
├── users
│   ├── row
│   ├── row
│   └── row
│
├── orders
│
└── products
```

---

# 2. Flask 本身不提供数据库

Flask 是 Web framework。

它负责：

```text
HTTP request
    ↓
Python function
    ↓
HTTP response
```

至于数据存在哪里，Flask 并不规定。

你可以使用：

```text
SQLite
PostgreSQL
MySQL
...
```

Flask 官方也把 Flask-SQLAlchemy 作为 SQLAlchemy 与 Flask 集成的一种常见扩展方式。([Flask 文档][1])

我们入门先选择：

> **SQLite**

因为 SQLite 不需要运行独立数据库服务器，它是一个嵌入式、serverless 的 SQL 数据库，整个数据库可以直接存放在普通磁盘文件中，非常适合学习和小型项目。([SQLite][2])

---

# 3. SQLite 长什么样？

例如：

```text
project/
├── app.py
└── instance/
    └── app.db
```

这个：

```text
app.db
```

就是数据库。

它不是 JSON：

```json
{
  "users": [...]
}
```

而是真正的关系数据库文件。

里面可以有：

```text
app.db
│
├── users
├── orders
└── products
```

---

# 4. 数据库真正执行的是 SQL

例如创建用户表：

```sql
CREATE TABLE user (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(200)
);
```

插入：

```sql
INSERT INTO user (name, email)
VALUES ('Alice', 'alice@test.com');
```

查询：

```sql
SELECT *
FROM user;
```

更新：

```sql
UPDATE user
SET name = 'Alice Smith'
WHERE id = 1;
```

删除：

```sql
DELETE FROM user
WHERE id = 1;
```

这四种操作极其重要：

```text
Create
Read
Update
Delete
```

合起来简称：

> **CRUD**

以后你会天天看到这个词。

---

# 5. CRUD 和 REST API 恰好可以对应起来

比如 User：

```text
数据库操作       HTTP

Create          POST
Read            GET
Update           PATCH / PUT
Delete          DELETE
```

于是：

```text
POST   /api/users
GET    /api/users/1
PATCH  /api/users/1
DELETE /api/users/1
```

后面实际上对应：

```text
INSERT
SELECT
UPDATE
DELETE
```

你可以把 REST API 和数据库联系起来：

```text
HTTP                  Database

POST /users      →    INSERT

GET /users/1     →    SELECT

PATCH /users/1   →    UPDATE

DELETE /users/1  →    DELETE
```

这就是大量普通 Web 后端的基本工作模式。

---

# 6. SQLAlchemy 是什么？

现在有一个问题。

难道 Flask 里每次都写：

```python
sql = """
SELECT *
FROM user
WHERE id = ?
"""
```

当然可以。

但 Python 项目通常会使用：

> **ORM：Object Relational Mapping**

SQLAlchemy 提供 ORM 能力；官方 SQLAlchemy 2.x 文档的核心模式就是把数据库表映射成 Python class，再通过 `Session` 持久化和查询 Python 对象。([SQLAlchemy 文档][3])

比如数据库：

```text
user
-------------------
id
name
email
```

映射成：

```python
class User:
    id
    name
    email
```

于是数据库里的一行：

```text
1 | Alice | alice@test.com
```

在 Python 看起来像：

```python
user.id
user.name
user.email
```

即：

```text
database row
      ⇅
Python object
```

这就是 ORM 最核心的思想。

---

# 7. Flask-SQLAlchemy 又是什么？

关系是：

```text
SQLite / PostgreSQL / MySQL
          ↑
       SQLAlchemy
          ↑
   Flask-SQLAlchemy
          ↑
        Flask
```

SQLAlchemy 是真正负责数据库抽象和 ORM 的库。

Flask-SQLAlchemy 是：

> 帮你把 SQLAlchemy 更方便地集成进 Flask。

它会帮 Flask 项目配置 engine、session 等常见对象，但并没有改变 SQLAlchemy 本身的工作方式。([Flask-SQLAlchemy][4])

安装：

```bash
pip install Flask-SQLAlchemy
```

官方当前 Flask-SQLAlchemy 3.1.x 文档假定使用 SQLAlchemy 2.x。([Flask-SQLAlchemy][5])

```text
project/
└── app.py
```

`app.py`：

```python

from flask_sqlalchemy import SQLAlchemy

app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///app.db"

```

这里：

```python
sqlite:///app.db
```

表示：

> 使用 SQLite 数据库。

而：

```python
db = SQLAlchemy(app)
```

把 SQLAlchemy 与 Flask application 绑定起来。

# 9. 定义第一张表

接下来定义 User：

```python
class User(db.Model):
    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    email = db.Column(
        db.String(200),
        unique=True,
        nullable=False
    )
```

你可以把它直接翻译成：

```text
User
│
├── id
│   Integer
│   Primary Key
│
├── name
│   String
│   NOT NULL
│
└── email
    String
    UNIQUE
    NOT NULL
```

对应 SQL 大致就是：

```sql
CREATE TABLE user (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(200) NOT NULL UNIQUE
);
```

ORM 的意义就非常直观了：

```python
class User(db.Model)
```

其实是在声明：

> 我要定义一张数据库表对应的 Python model。

---

# 10. 什么叫 Primary Key？

这里：

```python
primary_key=True
```

非常重要。

Primary Key：

> 唯一标识一行数据。

例如：

```text
id | name
---+------
1  | Alice
2  | Bob
3  | Alice
```

名字可以重复。

但：

```text
id
```

不能重复。

所以：

```text
id = 1
```

永远明确指向某一个用户。

因此 REST API 经常设计成：

```text
GET /users/1
GET /users/2
```

---

# 11. 创建数据库表

定义 model 不代表数据库中已经真的存在这张表。

需要：

```python
with app.app_context():
    db.create_all()
```

完整：

```python
from flask import Flask
from flask_sqlalchemy import SQLAlchemy

app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///app.db"

db = SQLAlchemy(app)


class User(db.Model):
    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )

    email = db.Column(
        db.String(200),
        unique=True,
        nullable=False
    )


with app.app_context():
    db.create_all()


if __name__ == "__main__":
    app.run(debug=True)
```

`create_all()` 会根据已经定义的 models 创建缺失的表；Flask-SQLAlchemy 文档也要求这类数据库操作在 Flask application context 中执行。([Flask-SQLAlchemy][5])

运行：

```bash
python app.py
```

就会产生 SQLite 数据库。

# 12. Create：插入数据

现在来看 CRUD 第一项。

创建用户：

```python
user = User(
    name="Alice",
    email="alice@test.com"
)
```

注意：

现在只是创建了一个普通 Python object。

还没有进入数据库：

```text
Python

User(...)
```

↓

```python
db.session.add(user)
```

↓

告诉 SQLAlchemy：

> 我打算把它写入数据库。

最后：

```python
db.session.commit()
```

才真正提交事务。

所以：

```python
user = User(
    name="Alice",
    email="alice@test.com"
)

db.session.add(user)

db.session.commit()
```

可以理解成：

```text
new Python object
       ↓
session.add()
       ↓
pending
       ↓
commit()
       ↓
database
```

SQLAlchemy ORM 官方也是通过 `Session.add()` 和 transaction commit 来持久化对象。([SQLAlchemy 文档][3])

# 13. 把它做成 REST API

我们已经知道：

```text
POST /api/users
```

表示创建 User。

因此：

```python
from flask import request


@app.route("/api/users", methods=["POST"])
def create_user():

    data = request.get_json()

    user = User(
        name=data["name"],
        email=data["email"]
    )

    db.session.add(user)
    db.session.commit()

    return {
        "id": user.id,
        "name": user.name,
        "email": user.email
    }, 201
```

客户端：

```bash
curl -X POST \
  http://127.0.0.1:5000/api/users \
  -H "Content-Type: application/json" \
  -d '{
        "name": "Alice",
        "email": "alice@test.com"
      }'
```

数据库变成：

```text
id | name  | email
---+-------+----------------
1  | Alice | alice@test.com
```

返回：

```json
{
  "id": 1,
  "name": "Alice",
  "email": "alice@test.com"
}
```

# 14. Read：查询数据

我们希望：

```text
GET /api/users/1
```

查数据库。

现代 SQLAlchemy 2.x 推荐使用 `select()` + session，而旧教程常见的 `Model.query` / `session.query()` 已属于 legacy query interface。([Flask-SQLAlchemy][6])

Flask-SQLAlchemy 提供一个方便的方法：

```python
user = db.session.get(User, user_id)
```

例如：

```python
@app.route("/api/users/<int:user_id>")
def get_user(user_id):

    user = db.session.get(User, user_id)

    if user is None:
        return {
            "error": "user not found"
        }, 404

    return {
        "id": user.id,
        "name": user.name,
        "email": user.email
    }
```

请求：

```text
GET /api/users/1
```

流程：

```text
GET /api/users/1
        ↓
Flask
        ↓
db.session.get(User, 1)
        ↓
database
        ↓
User object
        ↓
JSON
```

# 15. 查询所有用户

使用现代 `select` 写法：

```python
@app.route("/api/users")
def get_users():

    users = db.session.execute(
        db.select(User)
    ).scalars().all()

    return [
        {
            "id": user.id,
            "name": user.name,
            "email": user.email
        }
        for user in users
    ]
```

核心：

```python
db.select(User)
```

可以理解成：

```sql
SELECT *
FROM user;
```

SQLAlchemy 2.x 官方查询接口也是以 `select()` 作为主要查询构造方式。([SQLAlchemy 文档][7])

# 16. 条件查询

例如按 email 查询：

```python
stmt = db.select(User).where(
    User.email == "alice@test.com"
)

user = db.session.execute(
    stmt
).scalar_one_or_none()
```

对应 SQL 的思想：

```sql
SELECT *
FROM user
WHERE email = 'alice@test.com';
```

所以你可以开始理解 ORM 并不是魔法：

```python
db.select(User).where(
    User.email == email
)
```

本质是在构造：

```sql
SELECT ...
WHERE email = ...
```

# 17. Update：修改数据

API：

```text
PATCH /api/users/1
```

例如：

```json
{
  "name": "Alice Smith"
}
```

Flask：

```python
@app.route(
    "/api/users/<int:user_id>",
    methods=["PATCH"]
)
def update_user(user_id):

    user = db.session.get(User, user_id)

    if user is None:
        return {
            "error": "user not found"
        }, 404

    data = request.get_json()

    if "name" in data:
        user.name = data["name"]

    if "email" in data:
        user.email = data["email"]

    db.session.commit()

    return {
        "id": user.id,
        "name": user.name,
        "email": user.email
    }
```

注意这里没有：

```python
db.session.add(user)
```

因为 `user` 本身已经由当前 Session 加载并被 Session 管理。

你修改：

```python
user.name = ...
```

然后：

```python
db.session.commit()
```

SQLAlchemy 会把相应变化同步到数据库。

# 20. `db.session` 到底是什么？

这是数据库部分最值得理解的概念之一。

不要把：

```python
db.session
```

理解成“数据库”。

更准确来说，它是：

> **Python 对象世界和数据库 transaction 之间的工作上下文。**

例如：

```python
alice = User(...)
bob = User(...)

db.session.add(alice)
db.session.add(bob)
```

此时 Session 记录：

```text
准备 INSERT Alice
准备 INSERT Bob
```

然后：

```python
db.session.commit()
```

统一提交。

SQLAlchemy 的 `Session` 同时承担 ORM 对象状态管理和 transaction 交互等职责。([SQLAlchemy 文档][7])

---

# 21. 为什么必须 `commit()`？

假设银行转账：

```text
Alice -100
Bob   +100
```

你显然不希望发生：

```text
Alice -100 成功
Bob   +100 失败
```

数据库 transaction 希望：

```text
两个操作全部成功
```

或者：

```text
全部失败
```

所以：

```python
alice.balance -= 100
bob.balance += 100

db.session.commit()
```

把它们作为一个 transaction 提交。

如果中间出现异常：

```python
try:
    ...

    db.session.commit()

except Exception:
    db.session.rollback()
```

就可以回滚 transaction。

这是数据库非常核心的概念。

# 23. 和 Blueprint 结合

上一节我们刚学了 Blueprint。

现在项目就可以拆成：

```text
project/
│
├── app.py
│
├── extensions.py
│
├── models/
│   └── user.py
│
└── routes/
    └── users.py
```

这里一个很常见的模式是：

### extensions.py

```python
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()
```

### models/user.py

```python
from extensions import db


class User(db.Model):

    id = db.Column(
        db.Integer,
        primary_key=True
    )

    name = db.Column(
        db.String(100),
        nullable=False
    )
```

### routes/users.py

```python
from flask import Blueprint
from extensions import db
from models.user import User


users_bp = Blueprint(
    "users",
    __name__,
    url_prefix="/api/users"
)


@users_bp.route("/")
def get_users():

    users = db.session.execute(
        db.select(User)
    ).scalars().all()

    return [
        {
            "id": user.id,
            "name": user.name
        }
        for user in users
    ]
```

### app.py

```python
from flask import Flask

from extensions import db
from routes.users import users_bp


app = Flask(__name__)

app.config["SQLALCHEMY_DATABASE_URI"] = \
    "sqlite:///app.db"

db.init_app(app)

app.register_blueprint(users_bp)


with app.app_context():
    db.create_all()


if __name__ == "__main__":
    app.run(debug=True)
```

Flask-SQLAlchemy 官方支持这种先创建 `db`、之后通过 `init_app()` 绑定 application 的模式，这也更适合后续 Application Factory。([Flask-SQLAlchemy][5])

## 接下来数据库部分还有两个非常重要的主题

我建议继续按照：

